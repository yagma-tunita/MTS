2026-07-03 更新说明

================================================================================
1. 修复：Honeypot 中间件拦截 /health 健康检查端点
================================================================================

文件：net/protect/honeypot.go

问题：defaultHoneypotPaths 包含 "/health"，导致健康检查请求被蜜罐中间件以 404 拦截。

修改：从 defaultHoneypotPaths 列表中移除 "/health"。


================================================================================
2. 修复：CORS AllowCredentials + AllowOrigin("*") 违反浏览器规范
================================================================================

文件：net/middleware/cors.go

问题：AllowOrigins: ["*"] 与 AllowCredentials: true 同时设置，浏览器规范禁止此组合。

修改：AllowCredentials 改为 false。如生产环境需要凭据，需显式指定域名白名单。


================================================================================
3. 修复：dao.InitDB() / dao.GetDB() 全局变量死代码
================================================================================

文件：internal/dao/dao.go

问题：定义了全局 DB 变量及 InitDB/GetDB 函数，但从未被任何代码调用。

修改：删除 DB 变量、InitDB 和 GetDB 函数。


================================================================================
4. 修复：CancelOrder 软/硬删除不一致
================================================================================

文件：internal/service/order_service.go

问题：取消订单时，order_cargo 使用软删除（UPDATE delete_time），而 segment_capacity_usage 使用硬删除（DELETE），行为不一致。

修改：统一为硬删除，与数据库表结构（无 delete_time 列）保持一致。


================================================================================
5. 修复：FindByPortAndOp 查询 voyage_berthing 时引用不存在的 delete_time 列
================================================================================

文件：internal/dao/voyage_cargo_note_dao.go

问题：添加了 Where("voyage_berthing.delete_time IS NULL")，但 voyage_berthing 表没有 delete_time 列，导致 SQL 报错 "Unknown column"。

修改：移除此过滤条件。


================================================================================
6. 修复：ExpectedDeparture/ExpectedArrival 字段在订单创建时被忽略
================================================================================

文件：internal/service/order_service.go

问题：createOrderRequest 包含 expected_departure/expected_arrival，且 CreateOrderRequest 结构体也有对应字段，但 CreateOrder 方法从未将这两个字段映射到 ShippingOrder 模型。

修改：解析日期字符串并赋值给 order.ExpectedDepartureDate / ExpectedArrivalDate。


================================================================================
7. 修复：ListOrders 缺少权限校验
================================================================================

文件：internal/handler/order.go

问题：CreateOrder 校验了 shipper 角色的 user_id 是否匹配，但 ListOrders 完全不做权限检查，导致托运人可以查询任意其他托运人的订单列表。

修改：添加与 CreateOrder 相同的角色/用户 ID 校验逻辑。


================================================================================
8. 修复：GetOccupiedTons 未排除已取消订单的容量占用
================================================================================

文件：internal/dao/segment_capacity_usage_dao.go

问题：取消订单时 segment_capacity_usage 记录被硬删除，但若存在孤立记录，容量检查会错误计算。已去除不存在的 delete_time 引用，还原为简洁查询。

修改：回退为原始查询（无 JOIN、无 delete_time 过滤）。


================================================================================
9. 修复：SegmentCapacityUsage 模型误加 DeleteTime 字段，导致插入 SQL 报错
================================================================================

文件：internal/model/segment_capacity_usage.go

问题：添加了 DeleteTime 字段，但数据库表无此列，GORM INSERT 时报 "Unknown column 'delete_time'"。

修改：移除 DeleteTime 字段。


================================================================================
10. 修复：SQL schema 中 segment_capacity_usage 误加 delete_time 列和索引
================================================================================

文件：sql/tables_mysql.sql

问题：在 segment_capacity_usage 表添加了 delete_time 列和索引，与实际表结构不一致。

修改：回退所有 segment_capacity_usage 的 schema 修改。


================================================================================
11. 修复：订单创建后默认 status=1 但测试文档误写为 0
================================================================================

文件：桌面 MTS_从头测试.txt

问题：测试文档中状态更新步骤指示从 0→1 开始，但订单创建后实际 status=1（已确认），导致 {"status":1} 报 "invalid state transition"。

修改：更新测试文档，改为从 1→2（运输中）开始。


================================================================================
12. 修复：PowerShell 命令中 refresh_token 转义错误
================================================================================

文件：桌面 MTS_从头测试.txt

问题：$refreshBody = "{\"refresh_token\":\"$($login.data.refresh_token)\"}" 在 PowerShell 5.1 中解析报错 'UnexpectedToken'。

修改：改用 @{ refresh_token = ... } | ConvertTo-Json -Compress 方式构建 JSON。
